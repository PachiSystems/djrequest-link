Now Playing

now-playing watch listens to your Denon DJ / Engine DJ gear over StagelinQ and updates your venue's live display whenever the track in the mix changes.

Before you start

  • You've installed djrequest-link and saved your API key.
  • The venue's live display is turned on in your DJRequest.me admin. The tool checks this and won't start if it's off — Now Playing only ever appears on the live display.
  • Your plan includes the Now Playing feature. The API accepts updates either way, but the live display only shows them with that feature — so if everything looks fine here but nothing appears on screen, check your plan first.

Set up at a gig

  1. Put your laptop on the same network as your gear

    Connect the laptop to the same router or switch as your Engine DJ players — a cable is more reliable than Wi-Fi. If you use a VPN, see no devices found.

  2. Check the tool can see your gear 
    $ djrequest-link now-playing devices

    You should see each player listed, ending with (deck state OK). On Windows, the first run shows a firewall prompt — allow access on private networks.

  3. Do a dry run 
    $ djrequest-link now-playing watch --dry-run

    Play a couple of tracks and mix between them. The tool prints what it would send, without sending anything — the quickest way to check it picks the right deck with your setup.

  4. Go live 
    $ djrequest-link now-playing watch --venue <venue-id>

    Leave it running while you play. Press Ctrl+C when you finish — the display is cleared as it stops.

Playing the same venue often? Set the venue once instead of passing --venue every time:

$ export DJREQUEST_VENUE_ID="<venue-id>"
$ djrequest-link now-playing watch
> $env:DJREQUEST_VENUE_ID = "<venue-id>"
> djrequest-link now-playing watch

How it decides what's playing

Several decks report at once — you're cueing the next track, blending two, or a finished track is still loaded. By default (--mode auto) a track counts as now playing once it has been heard in the room — playing with its channel fader up — for 10 seconds. When two tracks qualify, the one that came into the mix most recently wins.

  • Cueing in headphones never counts while the channel fader is down.
  • In a blend, the incoming track takes over 10 seconds after its fader comes up.
  • If the tool can't see a fader position for a deck (for example some players without a built-in mixer), the deck is treated as audible whenever it plays.

If that doesn't suit how you play, change it:

OptionUse it when
--min-play 20Long blends switch too early. Raise the seconds a track must be heard (0–600, default 10).
--fader-threshold 0.2A deck just barely up counts as playing. Set how far up (0–1, default 0.05) the fader must be.
--mode masterYou use sync, and want the tempo-master deck.
--mode deck:1Only one deck matters (1–4).
--verboseYou want to see every deck's state as the tool sees it.

What gets sent

Only the track title and artist. Nothing else from your gear — no file paths, no library details — is read or sent. The display is updated only when the track actually changes, and at most once every 5 seconds.

When the display is cleared

  • When you stop the tool with Ctrl+C.
  • When nothing has been playing for 3 minutes (change with --idle-clear <minutes>) — for example your gear is switched off or the network drops.
  • When your laptop wakes from sleep, until a track is confirmed again.

DJRequest.me keeps showing the last track it was sent until something clears it. If the laptop's battery dies or the tool is force-quit, clear the display by hand: djrequest-link now-playing clear --venue <id>.

djrequest-link only ever clears a track it set, so it won't remove something you entered by hand in the admin.

Testing without gear

Check the live display end to end without any hardware:

$ djrequest-link now-playing set --venue <id> --title "Test Track" --artist "Test Artist"
$ djrequest-link now-playing show --venue <id>
$ djrequest-link now-playing clear --venue <id>

Troubleshooting

No devices found

  • Make sure the laptop and players are on the same network, and the players are switched on and have finished booting.
  • Allow incoming UDP port 51337 in your firewall. On Windows, if you dismissed the prompt, allow Node.js in Windows Security → Firewall & network protection → Allow an app through firewall.
  • VPNs and multiple network adapters can get in the way. Tell the tool which adapter to use with --interface <your laptop's IP on the DJ network>.

“The live display is turned off for …”

Turn on the live display in that venue's settings in your DJRequest.me admin, then run the command again.

It says “Now playing: …” but nothing appears on screen

Check your plan includes the Now Playing feature, and that the live display page is open for the right venue.

The wrong deck shows up

Run with --dry-run --verbose to see what each deck reports, then adjust --min-play, --fader-threshold or --mode (see above). If your setup still confuses it, please open an issue with your gear model and the verbose output.

“Missing API key” / “API authentication failed (401)”

Run djrequest-link auth status --check. If the key was regenerated in your admin, save the new one with djrequest-link auth set-key.

“The API URL redirects …”

You passed an --api-url (or set DJREQUEST_API_URL) that redirects elsewhere. Use the address the message suggests. The tool never follows redirects with your key.

Known limitations

  • Early days: the StagelinQ support is new. If something doesn't work with your gear, an issue with your model and --verbose output helps a lot.
  • Denon X1800 / X1850 mixers are ignored, so channel fader positions from those mixers aren't used — the players' own state is.
  • Mixer channel faders are matched to decks by number (channel 1 ↔ deck 1).
  • Only title and artist are shown; the DJRequest.me API doesn't store BPM, key or artwork for Now Playing.
